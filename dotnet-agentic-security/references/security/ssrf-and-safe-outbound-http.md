# SSRF and Safe Outbound HTTP

Use this file when the user accepts URLs, callback targets, webhooks, remote fetches, image imports, agent tools, or any feature that makes server-side outbound HTTP requests.

## Must implement

- Allowlist expected schemes, hosts, and ports.
- Reject private, loopback, link-local, and metadata-service destinations where user input influences the URL.
- Resolve and validate DNS carefully; consider DNS rebinding risk for high-impact systems.
- Disable or constrain redirects.
- Apply request timeouts, response size limits, and content-type checks.
- Treat third-party API responses as untrusted input.

## URL policy example

```csharp
public sealed class OutboundUrlPolicy
{
    private static readonly HashSet<string> AllowedHosts = new(StringComparer.OrdinalIgnoreCase)
    {
        "api.contoso.com",
        "graph.microsoft.com"
    };

    public static Uri Validate(string candidate)
    {
        if (!Uri.TryCreate(candidate, UriKind.Absolute, out Uri? uri))
            throw new InvalidOperationException("Invalid URL.");

        if (uri.Scheme != Uri.UriSchemeHttps)
            throw new InvalidOperationException("Only HTTPS is allowed.");

        if (!AllowedHosts.Contains(uri.Host))
            throw new InvalidOperationException("Host is not allowlisted.");

        if (!uri.IsDefaultPort && uri.Port != 443)
            throw new InvalidOperationException("Unexpected port.");

        return uri;
    }
}
```

## HttpClient configuration

```csharp
builder.Services.AddHttpClient("SafeOutbound")
    .ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler
    {
        AllowAutoRedirect = false
    })
    .AddStandardResilienceHandler();
```

## Verification

- internal metadata IP is rejected
- localhost and private IPs are rejected when not explicitly allowed
- HTTP is rejected when HTTPS is required
- redirects to disallowed hosts are rejected
- oversized responses are stopped
- downstream JSON is validated before use

## Avoid

- Proxying arbitrary URLs for users.
- Fetching URLs generated by a model without policy checks.
- Trusting DNS names without considering the resolved address class for high-risk flows.
- Sending internal credentials or cookies to user-controlled destinations.
